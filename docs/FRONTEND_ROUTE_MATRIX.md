# Frontend route and user-journey matrix

- **Task:** FE-001 — Route and user-journey inventory
- **Baseline:** 20 September 2026
- **Depends on:** [`FRONTEND_REQUIREMENTS_TRACEABILITY.md`](FRONTEND_REQUIREMENTS_TRACEABILITY.md), [`FRONTEND_BACKEND_CONTRACT.md`](FRONTEND_BACKEND_CONTRACT.md), [`contracts/openapi.json`](../contracts/openapi.json)

This matrix fixes the URL, rendering, cache, locale, metadata, authentication, operation, recovery, and handoff contract before App Router files exist. `{locale}` is one of `en`, `ha`, `ig`, or `yo`. `{slug}`, `{sourceId}`, and `{reportId}` are opaque route identifiers returned or linked by the application; secrets never occupy a path or query string.

## 1. Shared route rules

- Locale is owned by the first path segment. A locale-less public request may be negotiated once by `proxy.ts` and redirected to a supported locale. A locale-less private mutation never guesses or rewrites sensitive input.
- Public canonical URLs include the selected locale and exclude ephemeral UI parameters. Each indexable public page emits `hreflang` alternates for available locales plus `x-default` to English.
- Search/filter parameters are canonicalised in stable order on the project directory. Tracking codes, handle credentials, report content, reviewer session state, signed URLs, and discovery run identifiers are never canonical or shareable query parameters.
- Public reads execute at request time through the server-only private API client. No route fetches the API during `next build`.
- Public catalogue/detail/source responses may use the API's `public, max-age=60`, `ETag`, and locale variance. All errors are no-store. Interactive POSTs and every private/reviewer surface are dynamic and no-store.
- Private routes emit `robots: noindex, nofollow, noarchive`; reviewer routes also avoid prefetch. Public source/detail pages return the same safe not-found presentation for unknown and hidden records.
- Source Scout is embedded inside the project detail and reviewer report detail. Mobile may present the panel as a full-screen dialog, but it does not create a new indexable route.
- `not-found`, `error`, and recovery copy use safe problem codes and request IDs. They never expose an internal URL, stack, provider credential, private field, or record-existence distinction.

## 3. User-journey route sequences

| Journey | Required sequence | Completion proof | Safe interruption/recovery |
| --- | --- | --- | --- |
| Understand a project | FR-01 → FR-02 → FR-03 → FR-04 → FR-03 | User can state promise, evidence-backed status, responsible body, gaps, and source. | Filters remain shareable; public pages may be cached offline with saved/checked dates. |
| Ask a trusted question | FR-03 Q&A → cited source FR-04 or insufficient-evidence state | Every factual statement links to same-response source. | Network/provider failure preserves question only in current memory and offers bounded retry; no raw question persistence. |
| Report safely and track | FR-03 → FR-05 → FR-06 → FR-07 | Fictional report accepted privately, code saved once, status remains public-safe. | Approved draft subset after warning; same idempotency key for unknown completion; no code recovery claim. |
| Optional repeat-reporter handle | FR-08 → FR-05 → FR-07 → FR-08 delete | Credentials shown once; linked statuses remain generic; deletion unlinks without deleting reports. | No recovery; refresh/direct entry explains loss; wrong credential never reveals existence. |
| Review and publish safely | FR-10 → FR-11 → FR-12 → exact preview/publish → public FR-03 | Human-reviewed separate update appears publicly without report/contact/evidence leakage. | Session expiry preserves no private client cache; conflict refetches current state; sign-out clears cookie. |
| Public Source Scout | FR-03 panel start → poll → result/citations/source cards | Results remain visibly discovered/not reviewed; contradictions/gaps preserved. | Poll pauses hidden/offline, resumes same run, stops at terminal; no second-run fallback. |
| Report-scoped Source Scout | FR-12 plan → exact preview/approval → poll → follow-up/source decision | Only approved safe query leaves; attach creates pending source and does not publish. | Private run never persists offline; stale plan rejected; session/scope rechecked on every request. |

## 4. Layout and navigation ownership

| Boundary | Owns | Must not own |
| --- | --- | --- |
| Root app layout | HTML/body, global metadata defaults, direction-contract comment after Circle 1, skip link target, font preload policy, safe request ID presentation boundary. | Locale messages, private session state, runtime API fetch at build. |
| Locale layout | Locale validation, `lang`, message provider, public navigation, language switch, locale alternates. | Silent fallback, translation review claims, private response caching. |
| Public shell | Product navigation, low-data control, trust/report/track entry, public footer and non-emergency framing. | Reviewer actions or private state. |
| Reviewer shell | Authenticated navigation, session-expiry handling, explicit sign-out, no-store/no-prefetch defaults. | Public cache, tracking credentials, domain authorisation. |
| Feature surface | Feature-specific data mapping, semantic states, next action, focus restoration. | Generic proxying, raw ORM/backend model knowledge, cross-feature private state persistence. |

## 5. FE-001 exit gate

- [x] All twelve required routes have an audience, job, action, operation set, render/cache/auth rule, locale/canonical/robots rule, material states, and handoff.
- [x] All six user-journey sequences identify completion proof and safe interruption behavior.
- [x] Source Scout is embedded in project/reviewer detail rather than split into an unapproved product area.
- [x] Secrets and private identifiers are excluded from URLs, canonical metadata, prefetch, public cache, and offline persistence.
- [x] Public routes remain request-rendered and useful without JavaScript; no build-time private API dependency is introduced.
- [x] Unknown/hidden public records and inaccessible private records have safe, non-disclosing handling.
