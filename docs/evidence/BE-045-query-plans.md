# BE-045 query-plan evidence

- **Date:** 2026-09-19
- **What:** `EXPLAIN (ANALYZE, BUFFERS)` of the public project list query (`shaidago.projects.catalogue.LIST_PROJECTS_SQL`) before and after revision `0006_public_query_indexes`.
- **Dataset:** 20,000 synthetic projects (5% hidden, 30% of English summaries contain the search word), one English translation each, two synthetic localities. Every row is generated by `scripts/query_plan_evidence.py`; none is real data. The pilot itself will hold about six projects, so this measures headroom, not current load.
- **Environment:** PostgreSQL 18 with pgvector in the local Docker Compose stack (`make infra-up-core`), default configuration, one connection, warm cache, a developer machine. Timings vary between runs and machines; the plan shapes are what matter.
- **Reproduce:** from `services/platform`, `uv run --env-file ../../.env python scripts/query_plan_evidence.py --projects 20000`, plus `--drop-index NAME` to measure one index alone.

## Results (execution time, ms)

| Query | No new index | Both indexes | Only search index | Only recent-order index |
| --- | ---: | ---: | ---: | ---: |
| newest first (page 1) | 10.5 | 0.07 | 10.1 | 0.07 |
| category filter | 3.8 | 0.07 | 3.8 | 0.06 |
| locality and status filter | 2.9 | 0.07 | 3.0 | 0.07 |
| full-text search | 70 | 3.6 | 18 | 57 |
| second page (keyset) | 0.8 | 0.02 | 0.7 | 0.03 |

## Decisions

- `ix_projects_public_recent` on `(updated_at DESC, id DESC) WHERE visibility = 'public'` lets the planner return rows already in the API's total order and stop at the `LIMIT`, removing the sort and the full join for the default, filtered, and keyset-paged lists (about 150 times faster here). It is partial because only public rows are ever listed.
- `ix_project_translations_search`, a GIN index on `to_tsvector('simple', title || ' ' || summary)`, serves the `q` filter. The search predicate was rewritten as a semi-join on translation text so the expression matches the index: it now matches the requested locale or English text, which is slightly broader than the earlier served-text match. Alone it cut search from 70 ms to 18 ms; with the recent-order index it is 3.6 ms.
- Existing indexes already cover the other paths: `uq_project_translations_project_id_locale` (translation lookup), `ix_projects_locality_id`, `ix_project_facts_project_id` and its update twin, and the citation unique keys (fact and update lookups).
- Not measured: the `verification` filter (an `EXISTS` over published facts, indexed by project) and detail queries, which touch a single project and a handful of rows.

## Limits

The `simple` text-search configuration does no stemming, and no evaluation of Hausa, Igbo, or Yoruba tokenisation was done; that needs a human-reviewed corpus. A larger or differently distributed dataset could change plans, so the script should be re-run when the row counts or query change.
